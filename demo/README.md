# eXist-oidc Demo

This demo shows a small basic example on how to secure your eXist-db applications with the code in this repo.
The example consists of a `docker-compose.yml`, a pre-configured realm in Keycloak, and all the coniguration you need to use the module.
The `Dockerfile` puts them together to set up the demo.

To run the demo, you can simply run

```Bash
docker compose up -d
```

You can access the resulting eXist-db container under http://localhost:8555 and the Keycloak container under http://localhost:8556.

To view the demo, open the URL, go to the oidc-demo application based on TEI Publisher, and log in using the credentials.

```RAW
oidc-demo
password
```

You should see in eXide that a new collection under `/db/system/security/Oidc` should have been created, with the `accounts` sub-collection containing the demo user.
On logout, you should be redirected to the TEI Publisher application, and because you are logged out from Keycloak, to the Keycloak login form.

The setup creates a second user with none of the allowed roles:

```RAW
oidc-wrong-group
password
```

On login, you should receive a 403 error because that user does not have one of the roles that are mapped to the `tei role` of the demo app.

## Demo Setup

The demo application is based on TEI Publisher with few changes to the default configuration of a small demo app, so the login uses the active session from the security manager instead of a separate login.

These changes add security-manager based login instead of only the session token of TEI Publisher.

You can find these changes in the configuration:
- new module under `modules/oidc-auth.xql` with a function that checks the security manager's effective user and logs it in if possible
- changes in `modules/lib/api.json`: the operation of the `/api/login` points to the auth function of the new oidc-auth module
- import of the new module in `modules/lib/api.xql` for successfuly resolving the `oidc-auth:login` function
- in `templates/menu.html`, a script is added that redirects the user to the logout URL of the OIDC auth

The second change to the minimalistic default application generated by TEI Publisher is the `templates/menu.html` which adds following snippet to the logout button:

```HTML
<script>
document.addEventListener('pb-login', function (ev) {
    console.log('pb-login event', ev.detail);
    if (ev.detail.logoutUrl) {
        window.location.href = ev.detail.logoutUrl;
    }
});
</script>
```

This causes the application to redirect to the Keycloak logout, effectively locking you out of the application.

If this does not work for you, you can try adding an additional link to the menu bar using e.g.

```HTML
<a login="" href="/exist/oidc/logout">Logout</a>
```

to test if it is an issue with the logout button or the filters.
